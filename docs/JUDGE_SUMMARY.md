## 一句话

**给智能体一场雨的雨量，它自己拉地形与城市数据、算出哪里会积水，并给出受影响的下穿隧道与地铁口清单——而且每一项结论都能被独立复算。**

技术底座：**Agnes Harness（AGH）+ 仅 Agnes 模型**（`agnes-3.0-flash`），8 个自定义工具通过插件注册。

---

## 三个最有说服力的证据

### ① 它能算，而且账是平的

南京主城区、100 mm 降雨，76.3 km²：

| 结论 | 数值 |
|---|---|
| 淹没面积 | 7.81 km² |
| **被淹下穿隧道** | **117 / 420 段**，其中**生命危险级（≥0.3 m）102 段**、**车行隧道 44 段** |
| **被淹关键设施** | **146 / 292 个**，其中**地铁口 80 个** |
| 受影响道路 / 建筑 | 1722 / 4751 条 · 1131 / 12080 栋 |
| 最需处置的点位 | **南京五十中 2.55 m**、**新街口地铁口 #2/#13 各 2.47 m**、张府园 #4 2.23 m、南京定淮门长江隧道 1.62 m |

> 为什么单列这两类：下穿隧道**从两端灌满、没有逃生路线**；地铁口进水**直接连通地下空间**。
> 混在"某条路湿了"的清单里，等于把最要命的风险和最不要紧的风险一起报出去。

### ② 它知道自己有没有算错

**五项指标全部由程序判定，不达标就在报告里失败，而不是由我们口头保证。**

| 指标 | 含义 | 阈值 | 实测 | 在哪看 |
|---|---|---|---|---|
| D01 | 水量平衡：降雨 = 初损+下渗+蓄量+溢出+出流+残差 | ≤1% | **0.000000** | 报告 JSON |
| D01b | 从**输出的栅格文件**重算蓄量，对撞解算器 | ≤1e-6 | **2.1e-16** | 报告 JSON |
| D03 | 同一套物理用 **JavaScript 从零重写**，比对结果 | ≤0.05 m | **0.0 m** | AGH 工具 `flood_crosslang_check` |
| D04 | CN ±20% 时淹没面积必须单调且有界 | ≤45% | **单调，30.0%** | 报告 JSON |
| D02 | 与江苏省公安厅公布的易涝点比对 | ≥70% | **11.1%（未通过）** | 见下 |

### ③ 它敢说自己在什么条件下不成立

拿 [江苏省公安厅 2015 年公布的南京 32 处易积水路段](https://gat.jiangsu.gov.cn/art/2015/7/20/art_6373_6620598.html)
做外部验证：**命中率 11.1%，排序检验 AUC 0.5193 ± 0.0573，z = 0.336 —— 与随机无法区分。**

我们做了对照实验排除"是不是我们自己定位不准"（改成求道路交点后 AUC 0.5193，结论不变），
并把原因写清楚了：那份清单记录的是**管网瓶颈型**易涝点，而本模型只模拟**地形驱动**的积水。

> **这个负结果没有被删掉。** 一个只报告通过指标的团队，交出的报告是没有信息量的。

## 我们证明了什么 / 没证明什么

| ✅ 已证明 | ❌ 未证明 |
|---|---|
| 数值内核与解析解逐位一致（5/5） | **没有与真实积水观测做过有效对比** |
| 水量账目闭合（0.000000），栅格与解算器一致（2.1e-16） | 不是水动力求解器：不管流速、到达时间、管网、河道顶托 |
| 结论不依赖单一语言（Python↔JS 差 0.0 m） | 土壤水文分组按 HSG C 假设，未接真实土壤数据 |
| 异常输入全部 fail-closed（4 类故障） | 降雨是情景设定值，非官方设计暴雨 |
| **28 条回归测试 + 15 项变异测试全部通过** | |
| **干净副本可复现，冷启动结果逐位相同** | |

> **一句话适用范围：本模型回答"地形上哪里会存水、存多深"，不回答"实际这场雨哪里会淹"。**
> 适用于内涝风险普查与疑点筛查，**不能**作为防洪调度或预警的唯一依据。

## 验证的严谨性：我能证明测试会失败

一个通过的测试套件**不能证明它测到了任何东西**。本项目这个坑踩了三次
（改了数据结构、故障注入注到没用的参数上、期望值用被测函数自己算）。

所以做了**变异测试**：故意把源码改坏，看测试会不会抓。

| 注入的破坏 | 结果 |
|---|---|
| 保留公式忘减 254 | ✅ 抓到 |
| 库容曲线改用填洼面高程（曾让库容≈0） | ✅ 抓到 |
| 把水铺到整个汇水区而非洼地面（曾造成 2.5% 不平衡） | ✅ 抓到 |
| 曝光用正向变换代替逆变换（曾让所有 OSM 要素落到栅格外） | ✅ 抓到 |
| 道路采样按"米"加密而函数要"像素"（曾让风险低估 3 倍） | ✅ 抓到 |
| 关掉高程包络检查 / CN 不钳制 | ✅ 抓到 |
| 只改文档字符串（对照组，**不应**被抓到） | ✅ 正确地没抓到 |

**10/10 抓到，0 个幸存者。** 第一次跑时有 3 个幸存者——那是三个"修了 bug 却没被测试锁住"的隐患。

## 一条命令复现

```bash
python -m floodkit selftest                    # 解析校核 5/5
python tests/test_floodkit.py                  # 回归测试 31/31
python tests/mutation_check.py                 # 变异测试 15/15 抓到
python -m floodkit samples --bounds 118.72 32.02 118.82 32.10 --cn-source landcover
python -m floodkit run --bounds 118.72 32.02 118.82 32.10 \
       --rain-mm 100 --cn 85 --cn-source landcover --tag demo --exposure
```

首次运行会下载约 186 MB 数据（**实测 107 秒**），之后从缓存读取。
**冷启动结果与缓存运行逐位相同**——缓存只影响速度，不影响结果。
