# 演示任务书与视频分镜

> 用途：① 直接复制进 AGH 的任务提示词；② 3–5 分钟演示视频的拍摄底稿。
> 原则：**视频里出现的每个数字，都必须来自当场真实运行**，不预录、不拼接假结果。

---

## 一、演示要证明的三件事

评审表里最容易被做丢的三项，正好也是这支视频的主线：

| 要证明的 | 用什么镜头证明 |
|---|---|
| **AGH 与模型执行闭环** | 模型自己规划 → 调工具 → 读反馈 → 验证 → 重试，轨迹视图全程可见 |
| **验证严谨性** | 五项客观指标当场跑出来；跨语言独立复算对撞 Python 结果 |
| **异常处理** | 现场喂进一份坏数据，系统**拒绝出图**并说清原因，不编造结果 |

## 二、任务书（复制进 AGH 的提示词）

### 主任务

```
帮我做一次城市内涝快速研判，研究区用南京中心城区。

范围（WGS84）：西 118.72，南 32.02，东 118.82，北 32.10

情景：一场 100 毫米的降雨。

请按下面的要求做，每一步都要留下结果：

1. 先跑一次内核自检，确认数值算法没问题。
2. 拉取研究区地形数据，然后用真实下垫面（土地覆盖）推算产流参数，
   不要用全区域一个常数。
3. 跑这次降雨事件，给出积水范围、最大水深、受影响的道路和建筑。
4. 用独立的方法验证结果，特别是水量平衡，误差要小于 1%。
5. 最后给我一份结论，并说明这个结果在什么条件下可信、什么条件下不可信。
```

### 追问（用来展示诊断能力）

```
刚才结果里最大水深有 4 米多，这个数可靠吗？帮我看一下是哪些位置、
为什么会这么深，以及这些位置能不能直接拿去用。
```

模型应当能指出：那几个点属于"又深又小的洼地"，已被标记为 `verify_required`，
极可能是 DEM 伪影或施工基坑，**不应作为区域代表水深引用**。

### 故障注入（现场演示异常处理）

```
我换一份数据再跑一次。
```

然后把下面任一文件交给它——**通过工具参数 `dem_file` 传入**
（`flood_run_event({bounds:[…], rain_mm:100, cn:85, tag:"bad_units", dem_file:"data/fixtures/bad_dem_units.tif"})`）。
这条路径**已由插件契约测试锁定**（`run_event-rejects-bad-dem`：outcome=rejected，未产出栅格）。

| 文件 | 注入的错误 | 系统的实际反应 |
|---|---|---|
| `data/fixtures/bad_dem_units.tif` | 高程被误写成英尺（×3.28084） | 质量门拒绝，`DEM_OUT_OF_ENVELOPE`，**不出图** |
| `data/fixtures/bad_dem_no_crs.tif` | 坐标系被剥离 | 加载阶段即拒绝，`source DEM has no CRS`，**不出图** |

命令行等价复现（录像前可先自行验证一遍；与工具调用走同一条代码路径）：

```
python -X utf8 -m floodkit run --bounds 118.72 32.02 118.82 32.10 \
       --rain-mm 100 --cn 85 --tag bad_units \
       --dem-file data\fixtures\bad_dem_units.tif
```

期望：`"outcome": "rejected"`，`DEM_OUT_OF_ENVELOPE`，**不产生深度栅格**。

> 讲这段时可以说：**"它宁可说'这份数据不能用'，也不给一个看起来正常的假结果。"**

## 三、预期工具链与轨迹

轨迹视图里应当能看到这样一条链（这是提交材料里"≥1 条工具调用链"的实物）：

| 顺序 | 工具 | 预期返回 |
|---|---|---|
| 1 | `flood_selftest` | 5 项解析校核全部通过 |
| 2 | `flood_fetch_dem` | 瓦片路径与缓存目录 |
| 3 | `flood_run_event` | outcome=ok，五项指标，淹没面积，道路与建筑清单 |
| 4 | `flood_verify_report` | 独立重算水量平衡，fatal=0 |
| 5 | `flood_crosslang_check` | Python 与 JavaScript 结果一致，水位差 0.0 m |
| 6 | `flood_run_event`（坏数据） | outcome=rejected，无栅格产出 |
| 7 | `flood_crosslang_check`（负向对照） | 抓到人为改动，fatal=1 |

其中第 2、3 步是写操作，**应当弹出审批请求**，需要人工点"允许"——这是要在视频里
明确展示的一环：AGH 默认不会让模型随便动你的文件。

## 四、视频分镜（3 分 30 秒版）

| 时间 | 画面 | 旁白要点 |
|---|---|---|
| 0:00–0:20 | 问题场景：南京内涝新闻画面或地图 | "一场暴雨之后，哪些路会淹、多深、多少栋楼受影响——这个问题通常要等雨停了才知道。" |
| 0:20–0:40 | AGH 工作台全景 + 输入任务书 | "我们把这个问题交给一个跑在 Agnes Harness 上的智能体。这是任务书。" |
| 0:40–1:10 | **规划阶段**：模型输出计划 | "它先规划：自检 → 取数据 → 建模 → 验证 → 出结论。" |
| 1:10–1:40 | **审批弹窗**：拉数据 / 跑模型要审批 | "注意这里：AGH 默认不让模型直接动文件，写操作要先经我批准。" |
| 1:40–2:20 | **结果展示**：淹没图 + 下穿隧道/地铁口清单（含 `_critical.png` 点位图） | "跑完了。7.81 平方公里积水。但真正要看的是这一页：**117 段下穿隧道被淹，102 段是生命危险级，其中 44 段是车行隧道**；**80 个地铁口进水**——新街口那两个各 2.47 米，定淮门长江隧道 1.62 米。" |
| 2:20–2:50 | **验证阶段**：五项指标 + 跨语言复算 | "但重点不是这张图，是它怎么证明自己对。水量平衡精确闭合，误差是 0；水量从栅格重新积分与解算器一致到 1e-16；同一套算法我们用另一种语言重写，水位差 0。**这些不是我们说的，是程序判的。**" |
| 2:50–3:10 | **异常处理**：喂坏数据 → 拒绝 | "如果数据有问题会怎样？我们把高程单位换成英尺再跑——它拒绝出图，并告诉我数据不能用。**它宁可说不知道，也不给一个看起来正常的假结果。**" |
| 3:10–3:30 | 轨迹视图 + 结尾 | "整个过程 AGH 都留了痕：模型调用、工具调用、审批记录。这是它能被信任的原因。" |

## 五、录制前检查清单

- [ ] AGH 服务已启动，工作台可打开（双击 `启动AGH.cmd`）
- [ ] 已在 Settings → Models & accounts 配好 Agnes 模型
- [ ] 已在 Settings → Plugin management 安装并启用 `file:./flood-tools`
- [ ] 工具列表里能看到 8 个 `flood_*` 工具
- [ ] 数据已预热（DEM / 土地覆盖 / OSM 已缓存），避免录像时卡在下载
      —— 预热命令：先手动跑一次 `python -m floodkit run ... --exposure`
- [ ] 屏幕分辨率 1920×1080，浏览器缩放 100%，隐藏书签栏
- [ ] 关闭微信/QQ 等弹窗通知
- [ ] 录屏工具已就绪（ffmpeg / OBS / Windows 自带 Xbox Game Bar）
- [ ] 视频最终 3–5 分钟，**只提交链接**（需 1 个主链接，可选 1 个备用）

## 六、旁白里必须出现的关键数字（来自真实运行）

| 数字 | 含义 |
|---|---|
| 0.000000 | 水量平衡闭合误差（阈值 1%） |
| 2.1e-16 | 栅格重积分与解算器的相对差（阈值 1e-6） |
| 0.0 m | Python 与 JavaScript 双实现水位差（阈值 0.05 m） |
| 76.3 km² | 研究区有效分析面积 |
| 7.81 km² | 淹没面积（占研究区 10.2%） |
| **117 / 420 · 102 · 44** | 被淹下穿隧道段数 · 其中生命危险级 · 其中车行隧道 |
| **146 / 292 · 77** | 被淹关键设施数 · 其中地铁口 |
| 1722 / 4751 | 受影响道路条数 |
| 1131 / 12080 | 受影响建筑栋数 |
| 8/8 | 三类测试样例期望满足数 |
| 31/31 · 42/42 · 23/23 | Python 回归测试 · 插件契约测试 · 智能体路径彩排 |

> 最有力的两个镜头数字：**"80 个地铁口进水"** 和 **"新街口地铁口 2.47 米"**。
> 新街口是南京最核心商圈；另有 **南京定淮门长江隧道 1.62 米**、**南京五十中 2.55 米**。
> 评委一听就知道这不是纸上谈兵。

> ⚠️ 这些数字会被评委复核。**重新录制前若代码有改动，必须重跑一遍并更新数字**，
> 报告文件在 `data/runs/<tag>/` 与 `data/evidence/samples/`。
