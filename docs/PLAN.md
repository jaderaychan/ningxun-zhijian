## 1. 一句话定位

**给一个真实地点和一场真实降雨，让智能体自己规划、自己调工具、自己算出内涝淹没范围，并且在没人盯着的情况下自己证明"这个结果是对的"——证明不了就自己找原因、修参数、重算，最后交出一份带完整证据链的研判报告。**

我们要打的不是"效果图好看"，而是评审表里最容易被做丢的三项：**验证严谨性、异常处理、AGH 执行闭环**。

## 4. 系统架构

```
        用户任务书（地点 + 降雨情景 + 决策问题）
                     │
      ┌──────────────▼──────────────┐
      │   AGH（智能体运行与执行底座）│
      │  规划 → 调工具 → 读反馈 → 验证 → 重试
      └──────────────┬──────────────┘
                     │  AGH 后端插件注册的 8 个工具（JS）
   ┌──────────┬──────┴───────┬────────────────────┬──────────────────┐
   ▼          ▼              ▼                    ▼                  ▼
selftest  fetch_dem    run_event          verify_report     crosslang_check
（解析校核）（拉数据） （完整事件）        （JS 重算水量平衡）（JS 独立解算水位）
   │          │              │                    │                  │
   └──────────┴──────┬───────┴────────────────────┴──────────────────┘
                     ▼
        floodkit（Python 科学内核）  ←→  独立验证器（JavaScript）
```

**关键设计原则：模型负责规划与诊断，正确性由确定性工具与验证器保证。**
`agnes-3.0-flash` 免费且够用，但我们不依赖模型"算得对"，而是让它"调度得对、诊断得对"。

### 数据（全部公开、实测可直连）
| 数据 | 来源 | 用途 | 实测 |

| Copernicus DEM GLO-30 | AWS 公开桶（无需密钥） | 地形、坡度、洼地、流向 | 46.5 MB / 9.6 s |

### 计算链路
```
DEM(GLO-30) → 度量投影(UTM 50N，地理坐标系下格子面积随纬度变化)
→ 质量门(缺失/量纲/坐标系/量程) → 优先淹没填洼 → D8 汇流 → 洼地单元
→ 土地覆盖复合 CN → SCS-CN 产流(P = Ia + F + Q)
→ 各单元水位—库容曲线求平衡水位 → 逐格淹没深度
→ 多源验证 → OSM 承灾体叠加 → 决策清单
```

### 模型声明
**简化水文—地形（洼地蓄水）模型，不是二维水动力求解器。**
不回答流速、到达时间、管网排水、河道顶托。完整局限见 `docs/LIMITATIONS.md`（8 项）。

## 6. 验收标准（全部机器可判）

| 编号 | 指标 | 阈值 | 判定方式 |
|---|---|---|---|
| D01 | 水量平衡闭合误差 | ≤ 1% | `降雨 = 初损 + 持续下渗 + 蓄量 + 溢出 + 出流 + 残差` |
| D01b | 栅格 vs 解算器蓄量 | ≤ 1e-6 | 从**输出的栅格文件**重算，与解算器内部汇总比对 |
| D02 | 已知易涝点命中率 | ≥ 70% | 与公开易涝点清单比对（需真值清单） |
| D03 | Python / JavaScript 双实现一致 | 最大水位差 ≤ 0.05 m | 两套独立实现交叉 |
| D04 | 参数敏感性 | 单调且 ≤ 45% | CN ±20% 扫描；容差由 SCS 非线性推导 |
| D05 | 数据质量与降级正确性 | 100% 识别注入故障 | 故障注入用例 |

## 11. 关键技术备忘（踩过的坑，避免重来）

1. **AGH 必须源码构建**，Node ≥24.10 + pnpm 10.34.5（用 corepack 固定版本）。
2. pnpm 默认符号链接布局会让 Windows 上的 tsx 解析相对导入失败 → **必须 `--node-linker=hoisted`**。
3. 构建前需 Node 头文件：`node-gyp install --target=<ver> --devdir=<cache>`，并设 `AGNES_NODE_HEADERS`。
4. AGH 的"私有目录"ACL 校验会拒绝被沙箱改过 ACL 的路径 → **AGH_HOME 用默认 `~/.agh`**。
5. `AGNES_PROFILE` 只能用内置模板名（如 `local-dev`）。
6. rasterio 读 `/vsicurl/` 时 GDAL 的中文错误会触发 UTF-8 解码异常掩盖真实错误；
   **本机 GDAL 的 curl/schannel 也无法建立 TLS 连接** → 一律先用 Python 下载瓦片再本地读取。
7. AGH 的 `file:` 包源受 schema 限制为 `file:./` 开头且不允许 `..` → 插件必须先复制进仓库目录。
8. AGH CLI 的 `confirmPackageInstall` 要求 stdin/stdout **都是 TTY**，否则一律判"未同意"（INV-33）→ 安装只能走 Web 工作台。
9. **中文文本一律用文件工具编辑，绝不用 PowerShell 做字符串替换**（PS 5.1 按 ANSI 读写，会不可逆损坏 UTF-8 文件）。

### 已修复的十一个真 bug（全部写入回归测试）

1. `fill_depressions` 把 NaN 无效格连同 NaN 高程推入优先队列 → 堆序被破坏，全图 98% 被判为洼地。
2. `run_ponding` 用**填洼后**高程建水位—库容曲线 → 库容≈0，水位顶到溢出口，蓄量虚高 570 倍。
3. 水量平衡漏掉 SCS 的**持续下渗 F** → 29.7% 假误差。
4. 暴露分析世界坐标→栅格坐标用了正向仿射 → 所有 OSM 要素跑到栅格外，报告"0 条道路被淹"而**不报错**。
5. 建筑足迹采样步长误用**米**（14 px）→ 小建筑内采不到点，报告"0 栋建筑受影响"。
6. 把陡坡汇水区（33.6°）沟谷当成"4 米深积水潭"上报 → 现按局部坡度界定适用域，两组数字都给。
7. 测试样例构造器用 `None` 当"未传参"哨兵 → "缺 CRS"失败样例**静默跑成了正常分析**。
8. 质量门拒绝后未立即返回 → 缺 CRS 时在坐标变换里崩溃而非干净拒绝 → 改为 **fail-fast**。
9. 报告生成器零蓄量时格式化 `None` 崩溃 → 统一走 `_fmt()`，缺失输出 `n/a`。
10. 生成"坏数据"时沿用了源瓦片的完整 `profile`（含整块瓦片的 transform 与尺寸）→ 写出的文件**坐标与数据错位**，所谓"英尺高程"文件读出来根本不是英尺值，**故障注入演示等于假的**。现显式覆写 width/height/transform。
11. CLI 自带一套 `--envelope` 默认值（−30..800），把库里收紧过的研究区包络（−50..400）覆盖掉 → 英尺高程的 DEM **顺利通过质量门**，还生成了一张地形起伏放大 3.28 倍的淹没图。现统一为常量 `pipeline.DEFAULT_ENVELOPE`，并加回归测试锁住两端一致。
12. 道路采样时把"米"当"像素"传给加密函数（步长 14 像素 > 多数 OSM 路段长度）→ **每条路段实际只在起点采了一个点**，"淹没长度"退化成了"这段路起点是否在水里"。修复后风险被显著低估的事实暴露出来：被淹关键设施 46 → **143** 个，地铁口 27 → **77** 个，生命危险级下穿隧道 78 → **102** 段。**差了 3 倍。**
13. 洼地面判定与深度栅格的铺水范围不一致：水位—库容曲线只用"容量 > 报告阈值"的格子，水却铺在整个 D8 汇水区上 → **大研究区水量平衡出现 2.5% 残差**（小研究区当时只有约 0.6%，正好压在 1% 阈值下，所以一直没暴露）。诊断靠的是逐洼地核算缺口恰好等于全域残差(1,109,578 m³)。修复后 D01 从不足 1% 的残差降到 **0.000000**，并新增变异测试守护。


**第 4、5、7、10、11、12、13 条最危险：它们都不报错，只是安静地给出一个"看起来正常"的结论。**
第 5 条和第 12 条是**同一个错误犯了两次**（米/像素混淆），这正是"每个结论都要能复算"这条纪律的价值——
它第二次还是被测试抓了出来。这类 bug 读代码发现不了。
