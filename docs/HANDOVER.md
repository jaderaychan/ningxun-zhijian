## 二、为什么剩下两项我做不了

### AGH 执行记录

需要在 **AGH 会话里由 Agnes 模型自主调用工具**并留下轨迹。这要求：

1. 已报名并拿到赛事发放的 Agnes API Key（只有你能拿）
2. 在 AGH 里配置该 Key
3. 安装我们的插件（双击 `安装插件.cmd` → 按一次 `y`）
4. 让模型跑一次任务

我尝试过绕过第 1 步：用 AGH 官方自带的**回环模型**（`tools/acceptance/provider-fixture.ts`）
驱动工具。结论是走不通——AGH 在 Windows 上要求"已验证的服务端身份"才能连接命名管道
（`packages/sdk/src/transport/unix.node.ts:27`），而跨进程 SDK 连接返回 `TransportClosed`。

**这是刻意的安全设计，不是配置问题。** 另外插件安装也必须发生在真实 TTY 里
（`confirmPackageInstall` 的不变量 INV-33：未被回答的确认提示绝不能当作同意）——
所以我做好了 `安装插件.cmd`，但按那个 `y` 的人必须是你。

### 演示视频

需要先有上一条（视频的核心画面就是 AGH 里模型自主调用工具的过程），
并且需要你的账号发布到平台、拿到链接。

## 五、这个项目的核心主张

如果只记一句话：

> **一个只报告通过的指标的团队，交出的报告是没有信息量的。**

具体体现在：

- 五项指标**机器可判**，不达标就在报告里失败，不由我们口头保证
- **变异测试**证明这 28 条回归测试真的会失败（15 种破坏全部抓到）；
  第一次跑时有 3 个幸存者——三个"修了 bug 却没被测试锁住"的隐患
- 拿政府公布的易涝点清单做外部验证，**得出负结果**（命中率 11.1%，AUC 0.5193，
  与随机无法区分），并做了对照实验排除"定位不准"这一解释
- 该负结果没有被删，而是被转成一个能力：**判断上报积水点是"地形造成"还是"管网造成"**
- 报告里明写适用范围：**回答"地形上哪里会存水"，不回答"实际这场雨哪里会淹"**

## 六、答辩时的注意

准备好 13 个可能被问到的问题：`docs/DEFENSE_QA.md`。其中最要紧的一条：

**不要说"我们的模型能预测内涝"**，要说"我们的模型回答地形上哪里会存水，
不预测实际积水"。**答辩最容易失分的地方不是答不上来，而是过度声称。**

如果被问到没验证过的事，统一话术：

> "这一点我们没有验证过，它在 `docs/LIMITATIONS.md` 里属于第 N 条已知局限。
> 如果您希望，我可以在答辩后跑一组对照实验来回答。"
